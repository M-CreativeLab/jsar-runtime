# Trace 模块说明

## 模块功能简介

Threepio 的 trace（追踪）模块用于对整个 LLM 驱动的页面生成流程进行的流程追踪、性能分析和数据采集。它能够自动记录每个阶段（如规划、模块生成、DOM 操作等）的时间点、耗时、输入输出、异常等信息，

通过分析收集的信息，达成渐进式生成页面的目标。
### 渐进式指标

| 指标                          | 含义描述          | 阈值    |
| ----------------------------- | ----------------- | ------- |
| PFP（Page Frame Paint）       | 页面/应用框架绘制 | ≤ 1.8s  |
| CPI（Content Paint Interval） | 页面内容生成间隔  | ≤ 300ms |

主要功能包括：
- 自动追踪每个请求（如页面规划、模块生成、HTML 解析等）的开始、结束时间和耗时。
- 记录每个阶段的输入、输出、异常信息。
- 以结构化 trace 数据（如 trace.json）输出，便于后续分析和可视化。
- 支持多级嵌套追踪，完整还原 LLM 驱动的页面生成全流程。

## 如何使用 trace 模块

1. **自动集成**：
   RequestFlowManager 等核心流程类已自动集成 trace，无需手动调用。使用 `startSpan`，对目标函数作为callback，trace 数据会自动采集。

2. **事件监听**：
   可通过监听 RequestFlowManager 的事件（如 `append`）获取每个阶段的追踪数据。

3. **trace 数据输出**：
   执行流程后，会在指定目录生成 trace.json 文件，包含所有阶段的详细追踪信息。

## trace 数据结构说明

trace.json 主要包含：

| 字段名     | 说明                                                    |
| ---------- | ------------------------------------------------------- |
| input      | 用户的输入                                              |
| spans      | 每个阶段的追踪片段，含类型、开始/结束时间、异常、属性等 |
| timePoints | 关键时间点，便于分析各阶段耗时                          |
| callgraghs | 大语言模型的请求的关系                                  |

## 如何用 trace 数据优化提示词

1. **分析耗时**：
   - 通过分析 trace 的 spans ，可以定位 LLM 规划、模块生成 每个阶段的耗时瓶颈
   - 通过分析 trace 的 timePoints ，DOM 操作阶段的耗时瓶颈。
2. **定位异常**：trace 会记录每个阶段的异常信息，便 于发现提示词不合理导致的 LLM 误解或输出异常。
3. **优化 prompt**：根据 trace 发现的慢点或异常点，有针对性地调整 systemPrompt、workerPrompt 等提示词内容，提高 LLM 输出的准确性和效率。
4. **可视化分析**：可将 trace.json 导入可视化工具，直观分析流程瓶颈和优化空间。

## 示例：trace 优化流程

1. 执行页面生成，得到 trace.json。
2. 发现 planRequest 阶段耗时较长，分析 systemPrompt，发现描述不够精炼。
3. 优化 systemPrompt，缩短 LLM 响应时间。
4. 重新执行，trace.json 显示耗时明显下降。
